# Моделирование процессов и данных ООО «ТехноСервис» — практики №3–№6

Учебно-практический комплект моделей по сквозному примеру компании
**ООО «ТехноСервис»** (проектирование и разработка ПО): основной процесс
**A0 «Разработка программного обеспечения»** и его декомпозиция A1–A4.

| Практика | Нотация | Моделируемый процесс | Результат |
|---|---|---|---|
| №3 | **DFD, Гейн–Сарсон** | A1 «Анализ требований и проектирование» | диаграммы уровня 0 и уровня 1 + спецификация потоков данных |
| №4 | **IDEF3** | A3 «Тестирование и контроль качества» | диаграмма потока работ (UOB, перекрёстки `&` / `≥1`, объекты ссылок) + обоснование типов перекрёстков |
| №5–6 | **IDEF1X** | «Управление проектами разработки ПО» | логическая модель данных (8 сущностей, PK/FK, связи 1:M и 1:1) + спецификация атрибутов + DDL |

## Просмотр

* **Сайт-смотритель:** открыть `site/index.html` (все четыре диаграммы встроены как SVG,
  рядом — спецификации потоков, перекрёстков и атрибутов).
* **Отчёты:** `docs/practice-*.md` на GitHub или сводный `docs/otchet-praktiki-3-6.docx`.
* **Диаграммы:** `diagrams/*.svg` (печать/вектор), `images/*.png` (вставка в Word/презентации).

## Пересборка артефактов

Диаграммы и документы генерируются из кода — правьте `tools/data.py`
(содержание) или `tools/build_diagrams.py` (геометрия) и пересобирайте:

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
python tools/build_diagrams.py   # SVG + PNG
python tools/build_docs.py       # markdown + сайт
python tools/build_report.py     # DOCX
```

## Ключевые методические решения

* **DFD:** процесс A1 на уровне 0 сбалансирован с IDEF0 (входы/выходы/управление);
  уровень 1 содержит три подпроцесса (A13 и A14 IDEF0 объединены в 1.3), два хранилища
  и процесс-приёмник A2; проверка на «чёрные дыры» и «чудеса» выполнена.
* **IDEF3:** синхронные перекрёстки `&` (J3 — запуск ручного и автотестирования одной
  сборки; J2 — решение только после обоих видов тестирования) и асинхронные `≥1`
  (J1 — «баги найдены / багов нет», J4 — цикл регрессии); объяснено, почему не XOR.
* **IDEF1X:** идентифицирующие связи мигрируют составные ключи в потомков
  (ПРОЕКТ → ЗАДАЧА → ТЕСТ_КЕЙС → БАГ_РЕПОРТ), связь ДОГОВОР↔ПРОЕКТ — 1:1
  неидентифицирующая; модель нормализована до 3НФ и реализована в `sql/schema.sql`.
